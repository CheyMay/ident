Code9 IDENT Desktop 2.11.0
=======================

Что это
-------

Один агент на компьютере клиники выполняет три задачи:

1. Читает расписание IDENT через отдельную SQL-учетную запись только для чтения.
2. Каждые 10 минут отправляет врачей, филиалы, окна и каталог услуг на сервер Code9.
3. По отдельному переключателю может обрабатывать заявки через интерфейс IDENT.

Перед обработкой заявки робот ждет не менее 60 секунд без клавиатуры и мыши.
После подтвержденной записи агент сразу обновляет расписание на сервере Code9.

Агент запускается автоматически при входе текущего пользователя в Windows.
Это необходимо для робота: интерфейс IDENT доступен только в открытом сеансе
Windows. Фоновая часть и панель состояния запускаются двумя заданиями Windows.

Установка
---------

1. Распакуйте архив в обычную папку.
2. Запустите 1-Setup.cmd.
3. Введите IP SQL-сервера, пароль readonly_user и ключ агента Code9.
4. Мастер сам попробует найти instance, TCP-порт и доступную базу IDENT.
5. После установки в области уведомлений Windows появится значок Code9 IDENT.
6. Двойной щелчок по значку открывает состояние агента.

В панели видно:

- работает ли фоновая служба и автозапуск;
- есть ли связь с сервером Code9;
- когда расписание отправлялось последний раз;
- сколько получено врачей, филиалов, окон и услуг;
- включен ли робот и готов ли он к работе;
- последняя ошибка.

Автоматический поиск SQL
------------------------

Во время установки и по кнопке "Найти SQL автоматически" агент:

1. Проверяет активные соединения запущенного IDENT.
2. Запрашивает список instance через SQL Browser.
3. Проверяет сохраненный адрес и стандартный TCP-порт 1433.
4. Входит под readonly_user и получает только список доступных баз.
5. Определяет базу IDENT по имени и структуре таблиц.
6. Сохраняет сервер, instance, порт и базу в config.local.json.
7. Сразу выгружает schema-inventory.json без строк пациентов.
8. Фоновая служба передает эту структуру на сервер Code9, чтобы SQL-запросы
   расписания можно было подготовить без повторного подключения по AnyDesk.

Если несколько баз выглядят одинаково, мастер покажет короткий нумерованный
список. Нужно выбрать номер, а не перепечатывать название базы.

Расписание
----------

Выгрузку можно включать и выключать в панели или удаленно в расширенных
настройках виджета amoCRM. Кнопка "Отправить сейчас" запускает внеочередную
выгрузку. Кнопка "Проверить базу" открывает проверку SQL-подключения.

До настройки mapping.local.json панель покажет "нужна настройка расписания".
Сам агент, панель и удаленный мониторинг при этом продолжат работать.

После загрузки структуры специалист Code9 может сохранить проверенные
SELECT-запросы в расширенных настройках amoCRM. Агент получит их при следующем
сигнале, применит атомарно и сразу запустит внеочередную выгрузку. Повторно
подключаться к компьютеру клиники для редактирования mapping.local.json не нужно.

Удаленное обслуживание
----------------------

После первой установки специалист Code9 может без AnyDesk:

- запросить диагностический отчет без паролей и ключей;
- повторно запустить автоматический поиск SQL;
- указать найденные Data Source и название базы;
- перезапустить фоновый агент;
- назначить проверенную версию для автоматического обновления.

Пароль readonly_user остается зашифрованным на компьютере клиники. Сервер хранит
только техническое состояние, параметры подключения без пароля и последние
обезличенные строки журнала.

Робот заявок
------------

Робот после установки выключен. Кнопка "Проверить окно IDENT" снимает структуру
текущего окна, но НЕ обучает весь путь записи, не меняет рабочий профиль и не
включает выполнение заявок. Если IDENT завис, проверка останавливается через минуту.

Для настройки нужны отдельные снимки календаря, меню "Записать на прием" и окна
"Новый прием". Каждый снимок сохраняется в robot/ui-tree-ДАТА-ВРЕМЯ.json.
После этого специалист проверяет точные элементы и полный путь: пациент,
врач, дата, начало И конец приема, комментарий, сохранение и результат.

До автономной работы обязателен контрольный прием в реальном IDENT. Закрытие
окна или исчезновение кнопки сохранения не считаются подтверждением записи.
Если подходящих элементов нет в UI Automation, требуется отдельная доработка
под интерфейс клиники; повторное нажатие проверки само по себе это не исправит.

После включения робот обрабатывает только заявки, созданные позднее момента
активации. Накопленные тестовые заявки автоматически не исполняются.

Безопасность
------------

- SQL-команды изменения данных блокируются; разрешены только SELECT/WITH.
- Пароль SQL и ключ агента зашифрованы Windows DPAPI.
- Расшифровать их может только тот же пользователь на том же компьютере.
- Ключи и пароли не записываются в логи.
- ФИО и телефон пациента не записываются в логи робота.
- Файл тестовой заявки удаляется сразу после выполнения робота.
- После успешного действия робот сохраняет локальную квитанцию без данных
  пациента. При потере ответа сервера одна заявка не выполняется второй раз.
- Квитанция записывается самим UI-роботом сразу после подтверждения IDENT, до
  сетевого запроса и до завершения фонового процесса.
- При ошибке сохраняется локальный снимок окна IDENT; он не отправляется на
  сервер и нужен только для диагностики на компьютере клиники.
- До первого действия записывается robot/execution-pending.json. При сбое с
  неизвестным результатом новые записи приостанавливаются до ручной проверки.
  Этот файл нельзя удалять, пока не проверен результат в IDENT.
- При потере связи после сохранения повторяется только подтверждение серверу,
  а не ввод пациента. Для этого сервер также должен быть обновлен.
- Снимки и UI-деревья могут содержать данные пациентов. Не пересылайте их
  в общедоступные чаты и не включайте в обычный установочный архив.

Рабочая папка:

%LOCALAPPDATA%\Code9\IdentAgent

Лог:

%LOCALAPPDATA%\Code9\IdentAgent\logs\agent.log

Дополнительные команды
----------------------

2-First-Check.cmd          поиск SQL Server и проверка подключения
3-Export-Schema.cmd        выгрузка только структуры таблиц и колонок
4-Preview.cmd              предварительный просмотр расписания
5-Install-Autostart.cmd    повторная установка автозапуска
6-Run-Now.cmd              ручная отправка из консоли
7-Remove-Autostart.cmd     удаление автозапуска
8-Open-Status.cmd          открытие панели состояния
