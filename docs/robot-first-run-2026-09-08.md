## Порядок На Компьютере Клиники

1. Открыть Code9 IDENT. Проверить версию, службу и соединение с сервером.
2. Нажать «Отправить сейчас». Дождаться новой даты успешной выгрузки. Если SQL
   недоступен, сначала восстановить подключение. Ранее рабочий адрес из SSMS:
   `192.168.0.3,15000`, база `PZ`; это ориентир для проверки, не новый автопоиск.
3. Оставить робота выключенным. Открыть календарь IDENT и нажать в агенте
   «Проверить окно IDENT». Затем повторить для меню «Записать на прием» и
   открытого окна «Новый прием», а также для настроек времени/врача внутри него.
4. Каждый скан длится не больше минуты. Файлы `robot/ui-tree-ДАТА-ВРЕМЯ.json`
   сохраняются отдельно. Кнопка проверки не вводит пациента и не включает очередь.
5. Специалист проверяет доступность полей, выбор существующего пациента,
   открытие приема из календаря, дату, врача, начало, конец и подтверждение
   сохранения. Профиль и путь проверяются на реальном интерфейсе клиники.
6. Только затем провести согласованный контрольный прием на 45 минут.
   Проверить в IDENT ровно одну запись, ее реквизиты и занятость трех слотов
   после свежей выгрузки в amoCRM. Отдельно проверить интервал 2 часа.
7. До автономного запуска проверить остановку при активности пользователя,
   закрытом IDENT, блокировке Windows и повторное получение подтверждения
   после временной потери сети. Непонятный результат проверять вручную.

Не создавать новые тестовые заявки, пока не разобраны прежние. Не удалять
`execution-pending.json` ради принудительного запуска. Он означает, что робот
уже мог изменить IDENT, но результат требует проверки.

## Граница Готовности

Сохраненный ранее UI-скан содержит 22 элемента верхней панели, без календаря и
полей приема. Шаблон робота не является готовым адаптером календаря этой версии
IDENT. По скриншотам нельзя безопасно вычислить адреса динамических ячеек и
подтвердить UI Automation patterns. Если нужные элементы не доступны, понадобится
доработка адаптера, а не повторная установка или случайные клики по координатам.

При необходимости записать пациента до готовности робота используйте штатный
ручной ввод в IDENT. Не подтверждайте в amoCRM прием, который существует лишь в очереди.

## Изменения 2.11.0

- Запросы переключателей выполняются вне UI-потока, с сетевым таймаутом 15 секунд.
- Захват окна ограничен минутой; рабочий профиль сканированием не изменяется.
- Блокировка файла состояния/журнала не завершает процесс наблюдения за агентом.
- Запрос перезапуска ожидает завершения активной работы робота; зависший процесс
  по-прежнему останавливается по таймауту.
- Начало и конец приема обязательны; значения читаются обратно перед сохранением.
- Неоднозначные, скрытые и недоступные элементы не используются; исчезновение
  окна не считается доказательством создания приема.
- До UI-действий сохраняется локальная отметка. После неопределенного сбоя
  дальнейшие записи останавливаются. После подтвержденного сохранения
  повторяется только доставка результата серверу.
- Серверные изменения: истекшая аренда заявки переводится на проверку, а не
  повторно в очередь. Подтверждение идемпотентно; спорные слоты не открываются
  автоматически по истечении времени.

Клиентский архив и серверные изменения образуют один выпуск. Git push не означает
выкладку сервера. На момент этой проверки выпуск не назначен компьютеру клиники,
и новая серверная версия не развернута в production.

## Проверки Выпуска

- Backend: 55 тестов, последовательно.
- PowerShell: безопасность без IDENT, повтор подтверждения без второго ввода,
  таймаут после записи квитанции, неопределенный результат, интервалы 15–180 минут,
  сохранение часового пояса, заблокированный файл, отзывчивость окна и таймаут скана.
- Отдельная проверка обновления: сохранность секретов, SQL-маппинга и профиля,
  восстановление после поврежденного пакета.
- Панель отрисована на локальном тестовом состоянии. Реальный путь сохранения
  в клиентском IDENT пока не проверен.

UI-деревья и снимки могут содержать персональные данные. Хранить их локально,
передавать только уполномоченному специалисту; не помещать в установочный архив.
